## Почему SDK, а не прямые запросы

Работать с API можно напрямую — но SDK берёт на себя рутину, которую иначе придётся писать самостоятельно.

| Что делает SDK за вас | Без SDK |
|---|---|
| Типизированные методы с автодополнением в IDE | Ручное формирование запросов по документации |
| Автоматическая подстановка токена и заголовков | Самостоятельная настройка авторизации в каждом запросе |
| Встроенные ретраи при сетевых ошибках и rate-limit | Собственная логика повторных попыток |
| Обновляется вместе с API — ничего не сломается | Ручное отслеживание изменений в API |

<Note>
SDK — рекомендуемый способ интеграции. Прямые запросы к API подходят для быстрых тестов или языков, для которых SDK пока нет.
</Note>

## Установка

<CodeGroup>

```bash pip
pip install gmt-python-sdk
```

```bash npm
npm install gmt-typescript-sdk
```

```bash yarn
yarn add gmt-typescript-sdk
```

```bash pnpm
pnpm add gmt-typescript-sdk
```

</CodeGroup>

## Работа с API напрямую

Если SDK не подходит, API доступен без ограничений. Полное описание эндпоинтов — во вкладке [API](/sdk-reference). Спецификацию в формате OpenAPI можно [скачать](https://api.getmytg.com/docs/openapi.json).
